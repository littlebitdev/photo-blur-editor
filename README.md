# 사진 가림 편집기 (웹판)

인터넷 브라우저에서 여는 사진 개인정보 블러 편집기입니다.
**사진은 어디로도 업로드되지 않고, 여는 것부터 저장까지 전부 이 브라우저 안에서만 처리됩니다.**
(개발자 도구 → 네트워크 탭을 열어두고 써 보시면, 사진을 열거나 저장할 때 아무 요청도 나가지 않는 걸 직접 확인하실 수 있습니다. 얼굴 자동 찾기를 처음 쓸 때만 인식 모델 파일을 한 번 받아옵니다 — 아래 설명 참고.)

## 깃허브 페이지로 올리는 방법

1. 깃허브에 새 저장소(repository)를 만듭니다. (예: `photo-blur-editor`)
2. 이 폴더 안의 파일 **6개를 전부** 저장소에 그대로 올립니다(업로드 또는 `git push`): `index.html`, `app.js`, `sw.js`, `opencv.js`, `face_detection_yunet.onnx`, `haarcascade_frontalface_default.xml`
   - 나중에 `index.html`/`app.js`만 고쳐서 올릴 때는 새로고침 한 번이면 새 버전이 반영됩니다(이 두 파일은 인터넷이 되면 항상 최신본을 받습니다). `opencv.js`나 인식 모델 파일을 바꿨을 때만 `sw.js` 맨 위의 `CACHE_NAME` 숫자를 하나 올려 주세요.
   - `haarcascade_frontalface_default.xml`은 지금 쓰는 opencv.js(5.0.0)에는 실제로 없는 기능(Haar cascade)을 위한 예비 파일이라, **지금 당장은 안 올려도 프로그램이 그대로 잘 동작합니다.** 나중에 opencv.js가 이 기능을 지원하는 버전으로 바뀌는 경우를 대비해 남겨뒀을 뿐이고, 코드도 이 파일이 실제로 필요할 때만(YuNet을 못 쓸 때만) 불러오도록 되어 있어 평소엔 아예 받아오지도 않습니다. 저장소를 최대한 간단히 하고 싶으시면 이 파일은 빼셔도 됩니다.
   - `opencv.js`는 13MB 정도로 큰 파일입니다. 깃허브 웹 화면에서 파일을 끌어다 놓는 방식은 한 번에 25MB까지는 되니 문제없지만, 업로드가 느릴 수 있습니다.
3. 저장소의 **Settings → Pages** 로 들어갑니다.
4. **Branch**를 `main`(또는 올린 브랜치), 폴더는 `/ (root)`로 선택하고 저장합니다.
5. 1~2분 뒤 `https://<사용자아이디>.github.io/<저장소이름>/` 주소로 접속하면 바로 사용할 수 있습니다.

이후로는 그 주소만 열면 됩니다. 별도 설치나 파이썬, pip 같은 것이 전혀 필요 없습니다.

## 데스크톱 버전과 다른 점

- **저장 방식**: 데스크톱 버전은 "다른 이름으로 저장" 창이 뜨지만, 웹에서는 크롬·엣지 브라우저는 비슷하게 저장 위치를 고르는 창이 뜨고, 그 외 브라우저(사파리·파이어폭스 등)는 브라우저의 기본 다운로드 폴더에 자동으로 저장됩니다.
- **파일 형식과 압축**: 저장 창에서 PNG(무손실, 용량 큼) / JPEG(호환성 우선) / WebP(같은 화질에서 용량이 가장 작음) 중 고를 수 있고, JPEG·WebP는 압축률(화질) 슬라이더로 용량과 화질의 균형을 직접 조절할 수 있습니다. 문서에 첨부할 때는 WebP나 JPEG를 90 안팎으로 쓰면 눈으로는 원본과 거의 차이가 없으면서 용량은 크게 줄어듭니다. 크기 지정 칸은 원본 해상도보다 크게는 입력해도 자동으로 원본 크기로 제한됩니다.
- **얼굴 자동 찾기**: 데스크톱 버전과 **같은 계열의 알고리즘(OpenCV YuNet)** 을 브라우저용 공식 빌드(OpenCV.js, 버전 5.0.0)로 그대로 돌립니다. 이 버전의 OpenCV.js는 Haar cascade가 빠져 있어서 YuNet만 단독으로 씁니다 — YuNet이 더 정확한 최신 방식이라 문제되지 않습니다. 여기에 더해 ① 작은 사진은 미리 확대하고 ② 사진을 여러 구역으로 나눠 각각 인식한 뒤 합치는 처리를 자동으로 추가해서, 인원이 많은 사진에서도 잘 잡히도록 보완했습니다.
- **OpenCV.js를 받아오는 곳**: 평소엔 [jsdelivr](https://www.jsdelivr.com/)라는, 전 세계에서 하루에도 수십억 건씩 처리하는 대형 오픈소스 CDN에서 받아옵니다 — 이 프로젝트를 널리 공유해도 트래픽 걱정 없이 버틸 수 있는 곳입니다. 혹시라도 그 주소에 문제가 생기면(느리거나 접속이 안 되면) 저장소 안에 함께 넣어둔 `opencv.js` 사본으로 12초 안에 자동으로 전환됩니다 — 둘 중 하나만 살아있어도 정상 작동합니다. 인식 모델 파일(onnx, xml)은 처음부터 저장소 안에만 있어서 별도로 어디서 받아오지 않습니다.
- **자동 가리기 기능이 자동으로 준비됨**: 페이지를 열면 "자동" 항목의 상태 표시(●)가 곧바로 "준비하는 중…"으로 바뀌면서, 버튼을 누르지 않아도 백그라운드에서 알아서 준비가 시작됩니다. 사진을 열고 손으로 블러 영역을 그리는 등 다른 작업은 이 준비와 상관없이 바로 하실 수 있습니다. 준비가 끝나면 초록 점과 함께 "준비됐습니다" 문구로 바뀌고, 이 상태에서 「얼굴 한 번에 가리기」를 누르면 기다림 없이 바로 얼굴을 찾습니다. 「지금 준비하기」 버튼은 준비가 끝난 뒤 「다시 불러오기」로 바뀌는데, 캐시를 무시하고 처음부터 다시 확인하고 싶을 때 누르시면 됩니다(나중에 opencv.js를 새 버전으로 바꿔 올리는 경우 유용합니다). 실패하면 빨간 점과 안내 문구가 뜨고 버튼이 「다시 시도」로 바뀝니다.
- **새로고침해도 다시 받지 않음(서비스 워커)**: `sw.js`가 큰 파일들을 브라우저 저장 공간에 챙겨 둡니다. 페이지를 새로고침하면 상태 표시는 "준비하는 중…"으로 다시 잠깐 보이는데(브라우저가 새로 열릴 때마다 프로그램 자체가 새로 시작되는 거라 이건 자연스러운 동작입니다), 자동으로 다시 준비가 시작되고 이미 저장돼 있는 파일을 쓰기 때문에 눈 깜짝할 새에 "준비됐습니다"로 바뀝니다. 한 번이라도 성공적으로 써 본 브라우저라면, 그 뒤로는 인터넷이 없어도 얼굴 찾기가 계속 동작합니다.
- 상단 헤더의 실행 취소(↶)/다시 실행(↷) 버튼과, "사진 열기" 바로 아래의 회전 버튼은 편집 목록 안에 있던 것과 완전히 같은 기능이 자리만 눈에 잘 띄게 옮겨진 것입니다.
- 그 외 도구(사각형/원/자유 그리기/선택), 가림 방식(블러/모자이크/검은색), 강도 조절, 복사/붙여넣기는 데스크톱 버전과 동일하게 동작합니다.

## 로컬에서 미리 확인하는 방법 (선택)

깃허브에 올리기 전에 내 컴퓨터에서 먼저 열어보고 싶다면:

- 파일을 더블클릭해서 바로 여는 방식(`file://`)은 **얼굴 자동 찾기가 동작하지 않습니다.** 브라우저 보안 정책상 `file://`로 연 페이지는 같은 폴더의 다른 파일(opencv.js, onnx, xml)을 스스로 읽어올 수 없기 때문입니다. 이 경우 사진 열기·그리기·저장 등 나머지 기능은 정상 동작합니다.
- 얼굴 찾기까지 포함해 전부 미리 보려면, 이 폴더에서 아래처럼 간단한 로컬 서버를 하나 띄우고 브라우저로 `http://localhost:8000` 을 열면 됩니다.
  - 파이썬이 설치되어 있다면: `python -m http.server 8000`
  - Node.js가 설치되어 있다면: `npx serve .`

## 얼굴 자동 찾기가 "찾는 중"에서 멈춘다면

"자동" 항목의 상태 표시를 먼저 봐 주세요. 노란 점이면 준비 중, 초록 점이면 준비 완료, 빨간 점이면 실패이고 실패 이유가 바로 옆에 글로 표시됩니다. 8초쯤 지나면 진행 상황 안내로 바뀌고, 45초가 지나도 안 끝나면 자동으로 빨간 점 + 실패 메시지로 바뀌도록 만들어져 있습니다. (이전 버전에서는 사진 인식 모델 파일을 받아오는 부분에 시간제한이 없어서, 그 단계가 막히면 정말로 몇 분이고 멈춰 있을 수 있었습니다 — 이제는 그 부분에도 시간제한을 넣어서 반드시 몇십 초 안에 성공하거나 실패 메시지가 뜨도록 고쳤습니다.)

그래도 계속 멈춰 있다면:
- **브라우저 개발자 도구(F12) → Network 탭**에서 `opencv.js` 요청이 몇 번 보이는지 확인해 주세요. 정상이라면 `cdn.jsdelivr.net` 주소로 한 번 성공하고 끝나거나, 그게 느리면 12초쯤 뒤에 우리 저장소의 `opencv.js`로 한 번 더 시도하는 게 보일 수 있습니다. 두 시도 다 실패(빨간색)라면 다음을 확인해 주세요.
- 저장소에 `opencv.js` 파일이 실제로 올라가 있는지, 이름이 정확히 `opencv.js`인지 확인해 주세요.
- jsdelivr(`cdn.jsdelivr.net`)와 우리 저장소 양쪽 다 막혀 있을 가능성은 낮지만, 혹시 학교·회사 네트워크라면 둘 다 시도해 보이는지 Network 탭에서 확인해 주세요.
- **Console 탭**에 빨간 글씨 오류가 있다면 그 내용을 알려주세요.

## 단축키

- Ctrl+Z 되돌리기 / Ctrl+Y 다시 실행 / Ctrl+S 저장 / Ctrl+O 사진 열기
- Ctrl+C 선택한 가림 영역 복사
- Ctrl+V 붙여넣기 — 클립보드에 **사진**이 있으면 그 사진을 새로 불러오고(한글 문서·웹페이지·탐색기 등에서 이미지를 복사한 경우), 그게 아니라 복사해둔 **가림 영역**이 있으면 그 영역을 붙여넣습니다.
- Delete 선택 삭제 / 방향키 위치 미세 이동 (선택 도구일 때)
- 마우스 오른쪽(또는 가운데) 버튼 드래그로 화면 이동, 휠로 확대/축소

## 클립보드에서 바로 붙여넣기

사진 파일을 따로 저장하지 않아도, 한글(HWP) 문서나 웹페이지·탐색기에서 사진을 **복사(Ctrl+C)**한 뒤 이 페이지에서 **Ctrl+V**만 누르면 바로 불러와집니다. 파일 열기·드래그 앤 드롭과 똑같이 동작하고, 클립보드에 사진이 아닌 다른 내용(글자 등)이 있으면 아무 영향 없이 무시됩니다. 저장 창처럼 입력칸이 열려 있을 때는 그 칸에 평소대로 붙여넣기가 됩니다.

## 가림 영역 표시 (v=22)

- 모든 가림 영역에 얇은 테두리와 번호(1, 2, 3…)가 표시됩니다. 선택한 영역은 굵은 점선과 손잡이로 구분됩니다.
- 선택 도구에서 영역 위에 마우스를 올리면 미리 강조됩니다(클릭하면 그 영역이 선택됩니다).
- 상단의 "영역 표시" 버튼 또는 `H` 키로 켜고 끌 수 있으며, 설정은 브라우저에 기억됩니다.
- 표시는 화면용일 뿐 저장되는 사진에는 나타나지 않습니다.

## 클립보드에 복사 (v=26)

- 저장 창(크기·형식 선택 창)의 **클립보드에 복사** 버튼을 누르면, 선택한 크기(원본 또는 지정한 크기)의 가림 결과 사진이 클립보드에 들어갑니다. 한글·워드·메신저 등에 `Ctrl+V`로 바로 붙여넣을 수 있습니다.
- 클립보드에는 **PNG 형식**으로만 복사됩니다. 현재 웹 표준상 클립보드 이미지 복사는 PNG만 보장되어 있어서, 저장 창의 파일 형식·압축률 설정은 복사에는 적용되지 않고 저장(다운로드)에만 적용됩니다.
- 한글 문서 등에 넣을 때 용량을 줄이고 싶다면, JPG로 저장한 뒤 그 파일을 문서에 끌어다 넣는 방법을 권합니다.
